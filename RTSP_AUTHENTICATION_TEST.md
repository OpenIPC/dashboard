# Тест исправлений RTSP аутентификации

## Исправленный алгоритм обработки RTSP URL

1. Исходная проблема: RTSP URL с символами @ в пароле обрабатывались неправильно
2. Решение 1: Исправление передачи параметров между фронтендом и бэкендом
3. Решение 2: Улучшение алгоритма обработки URL с несколькими @ и другими специальными символами

## Тестовые случаи

1. Стандартный URL: `rtsp://admin:password@192.168.1.100:554/stream=0`
   - Ожидаемый результат: URL останется без изменений

2. URL с @ в пароле: `rtsp://admin:pass@word@192.168.1.100:554/stream=0`
   - Ожидаемый результат: `rtsp://admin:pass%40word@192.168.1.100:554/stream=0`

3. URL с @ в имени пользователя: `rtsp://user@name:password@192.168.1.100:554/stream=0`
   - Ожидаемый результат: `rtsp://user%40name:password@192.168.1.100:554/stream=0`

4. URL с / в пароле: `rtsp://admin:pass/word@192.168.1.100:554/stream=0`
   - Ожидаемый результат: `rtsp://admin:pass%2Fword@192.168.1.100:554/stream=0`

5. URL с пробелом в пароле: `rtsp://admin:pass word@192.168.1.100:554/stream=0`
   - Ожидаемый результат: `rtsp://admin:pass%20word@192.168.1.100:554/stream=0`

2. Функция `fix_rtsp_url` в `rtsp_utils.rs` улучшена для правильной обработки URL с несколькими @ и другими специальными символами

Новый алгоритм:
- Находит последний символ @ для правильного разделения аутентификации и хоста
- Корректно URL-кодирует имя пользователя и пароль
- Проверяет валидность сгенерированного URL для гарантии корректности
